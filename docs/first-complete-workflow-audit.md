## Confirmed fixes

1. Focus/manual refresh failures previously replaced the task/review subtree and discarded open forms. Transient failures now retain the last loaded record/form, show an inline warning and disable mutation until a successful refresh. Explicit 401/403 discards cached assignment data. Older refresh responses cannot replace newer ones; request-keyed dispatcher panels do not carry state between requests.
2. An unfinished evidence reservation with location consent previously reloaded with consent off and empty coordinates, causing immutable retry metadata to differ. Valid stored consent/coordinates now initialize the retry form; coordinates are disabled during submission. Files must still be reselected after a page reload, as required by browsers.
3. Thrown Storage/database transport errors previously fell into invalid-input HTTP 400 catches. Evidence and assignment operational failures now return a private/no-store 503 and preserve retry instructions. Failed byte readback never signs/finalizes; uncertain finalization or transition tells the user to refresh before retrying the same operation. The client requires the explicit matching success ID before announcing submission. The evidence proxy also returns a sanitized no-store error on thrown transport failures.
4. Dispatcher review previously offered approval even when the image had not loaded, and expired review controls remained enabled until the RPC rejected them. Approval/completion now wait for the current submitted photograph to load; historic images cannot unlock them. Expiration disables review controls. These are UI protections; RPC authorization, state and expiry remain the security boundary. An image load does not certify photo authenticity or prove thoughtful human review.
5. The verification store previously reused pre-mutation in-flight reads and could publish an old account's response after its last subscriber unmounted. Mutations now force a new read; unsubscribe invalidates/aborts old reads, and late responses are ignored even if the transport ignores abort.
6. The dashboard previously derived active/review/completed counts from request statuses that remain draft forever. Counts now come from assignments created by the current dispatcher, under verified auth/RLS. Missing activity data displays an unavailable value rather than a false zero. Budgets and spending are unchanged; drafts/samples are not field activity. SERV copy now distinguishes accepted instructions from review candidates and does not claim a request is unassigned regardless of its actual assignment.
